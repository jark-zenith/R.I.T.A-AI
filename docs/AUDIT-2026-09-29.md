# R.I.T.A architecture audit — 2026-09-29

## Architecture found

The project is an existing Next.js 16 + TypeScript App Router application.

Persistence/authentication boundary:
- Supabase Auth handles account identity and sessions.
- Supabase PostgreSQL stores application financial data.
- Row Level Security is enabled on user-owned tables.
- Server actions call the verified server-side Supabase session before mutations.
- Render hosts the Next.js web service.

Deployment:

## Findings addressed in this upgrade

1. The root route was private-only instead of being a public landing page. It is now public, with /dashboard protected.
2. Google OAuth UI/callback and password recovery were missing. Both flows are now implemented, but Google is not considered enabled until Supabase provider configuration is completed.
3. Budget update authorization did not re-check category ownership. Migration 004 replaces that policy with a cross-owner-safe relationship check.
4. Currency totals could be combined without an explicit currency boundary. Dashboard/report aggregation is now currency-scoped.
5. Transfers were not modeled as first-class records. Migration 004 adds transfers with same-currency ownership checks.
6. Daily user-submitted financial snapshots were missing. Migration 004 adds daily snapshots.
7. Financial correction history was incomplete. Transaction updates/deletes now create revision records.
8. Full user-data export was missing. An authenticated JSON export has been added.
9. A deletion-request state was missing. Settings can now record a deletion request for operational follow-up.
10. Security headers were missing. Baseline HTTP security headers are now set by Next.js configuration.

## Important remaining risks

- Supabase project credentials are not present in the repository/runtime, so database persistence cannot be verified from this coding connection until a real Supabase project is configured.
- The two-user RLS integration test is present but intentionally skipped without a dedicated test project and test accounts.
- Google OAuth cannot be declared functional until provider configuration and a real callback test are performed.
- Evening reports are generated on demand today. A privileged scheduler/notification service is not enabled because that would require a secure service identity and delivery provider.
- No bank/mobile-money/payment integration is enabled.
- The Render branch is 49 commits ahead and 1 commit behind main. Before merging, reconcile that divergence deliberately rather than force-resetting either branch.
- The financial engine stores fixed-precision minor units in PostgreSQL bigint. JavaScript display/report helpers use safe integer minor units; high-value or cross-system accounting should retain fixed-precision semantics end-to-end.

## Database durability

The intended production persistence layer is Supabase PostgreSQL. It survives Next.js process restarts and Render application redeploys because application state is not stored in the web process.

Before real financial use, apply migrations 001 through 005 to the intended Supabase project and verify backups/recovery.
